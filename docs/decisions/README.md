| `2026-11-05-simdjson-abi-bump-breaks-node.md` | A `brew install` of a node-dependent formula auto-upgrades `simdjson`, whose ABI bump (5.0.5 → 5.1.1, `libsimdjson.34.dylib` → `.36.dylib`) breaks `node` in **two layers**: a loud dyld "Library not loaded" (compounded by a missing `/usr/local/opt/simdjson` opt symlink), and — once you relink past it — **silent memory corruption** in node's native `internal/modules/package_json_reader`, which aborts with `std::bad_alloc` on any package.json containing a string value. Layer 2 is real, not a linker artifact: 56 of 251 public headers differ between the two upstream tags, including every `*/stringparsing_defs.h` and the DOM/ondemand parser headers, while `implementation.h` / `base.h` / `error.h` stay byte-identical — so a spot-check of the "stable" headers proves nothing. Decision: **pin `simdjson`**; **never** alias `.36` → `.34` (the mangled names survive the bump, so the link succeeds and the incompatibility resurfaces later as `bad_alloc`); repair by **rebuilding node against the installed simdjson** (`brew upgrade node` → 26.13.0_2), which is mutually exclusive with downgrading simdjson (5.0.5 ships only `.34`). Records the recovery trap: an interrupted `brew upgrade` leaves an empty `Cellar/<formula>/<newversion>/` dir, so `brew outdated` reports the new version as installed and the retry **no-ops**. | Active. |

| `2026-11-05-per-component-cold-storage-buckets.md` | Each component with a cold tier owns its **own bucket** — the substrate's shared-bucket design cannot isolate two writers, because the isolation mechanism (the key prefix) is only settable fleet-wide (`ONEIRIC__SUBSTRATE__COLD__PREFIX`), so two components sharing a bucket would share a prefix and overwrite each other's objects. The bucket name and prefix become component settings; the backend, compression, endpoint and region stay fleet-wide. `mahavishnu-cold` is deliberately not created — Mahavishnu has no cold tier. Also records why cold config drifted into the environment at all: `cold.bucket`/`cold.prefix` are substrate-mapped, so `_strip_substrate_mapped` removes them from every YAML layer *including the XDG overlay*, and Oneiric's source chain puts env vars **above** all YAML layers. Related: **no component config in `.envrc`** — it is a direnv hook, so it is directory-scoped (a launchd service sees a different config than a dev shell) and its exports outrank the XDG overlay. Three Bodai repos set component config there today: `akosha` (a **dead, tracked** `AKOSHA__STORAGE__HOT__PG_URL` — `pg_url` is a *warm* field, and the value is a credentialed URL committed since 2025-02-01), `oneiric` (a live, tracked `HEALTH_FEED_HALFLIFE_SECONDS`), and `opera-cloud-mcp` (14 vars incl. a client secret, but correctly gitignored).
