# Master Plan Index + Centralized Regenerator — Design Spec

## Goal

A single `PLAN_INDEX.md` in `mahavishnu/docs/plans/` (the "master") that aggregates the plan/decision/spec corpus across all Bodai core components. Sibling repos keep their own local `PLAN_INDEX.md` for fast local navigation; the master is the convergence view. The 7 forked `regenerate_plan_index.py` scripts collapse into one shared library in `oneiric.plan_index`.

## Background

Today (2026-10-19):
- 7 Bodai core repos each ship their own copy of `regenerate_plan_index.py` (and mahavishnu has 5 additional plan-index scripts: `audit_plan_index.py`, `bootstrap_plan_index.py`, `backup_plan_index.py`, `restore_plan_index_backup.py`, `backfill_plan_spec_titles.py`, `_apply_plan_audit_2026_09_12.py`).
- mahavishnu's `docs/plans/PLAN_INDEX.md` frontmatter claims `topic: convergence-control-plane` ("Navigation map for finding and reviewing active Mahavishnu/Bodai plans") but the regenerator only walks mahavishnu's own tree. The claim is aspirational; the artifact doesn't deliver.
- One open bug surfaced during this design: `crackerjack/crackerjack/tools/plan_index_sync.py:DEFAULT_STORES` lists `docs/plans/` twice; oneiric's PLAN_INDEX.md (regenerated by crackerjack's hook) had a verbatim duplicate `### Docs: plans` block. **Fixed as a side task on 2026-10-19.** Surfacing this in the spec so we don't regress during the larger refactor.

## Architecture

The regenerator logic moves into `oneiric/plan_index/` as a shared library. Per-repo regeneration goes through crackerjack's existing fast-hook, which now imports the library instead of carrying its own implementation. The master regenerator lives in `mahavishnu/plan_index/` and consumes the same library for each `emit_in_master: true` entry in `settings/repos.yaml`, appending a `## Cross-repo plans` section to mahavishnu's local `PLAN_INDEX.md`. There are no inbound surfaces in sibling repos: they keep generating their own `PLAN_INDEX.md` locally; the master pulls them at regeneration time.

## Decisions (locked in brainstorming)

1. **Master PLAN_INDEX.md lives in `mahavishnu/docs/plans/PLAN_INDEX.md`** — single file with both mahavishnu-local content and a `## Cross-repo plans` section (variant A).
2. **Shared regenerator library lives in `oneiric/plan_index/`**.
3. **Sync model: pull on regeneration** — master walks siblings at read time. No push surface in sibling repos. No cron, no webhook.
4. **Discovery reuses `mahavishnu/settings/repos.yaml`** — already declares `path/tags/description` per repo. Add optional `emit_in_master: true` to opt in.
5. **Fork disposition: delete the 7 forks** per `feedback-no-backwards-compat-pre-1.0.md`. Crackerjack's `crackerjack/tools/plan_index_sync.py` rewires to `oneiric.plan_index` and remains the per-repo fast-hook.

## Component responsibilities

### `oneiric/plan_index/` (new shared library)

```
oneiric/plan_index/
    __init__.py            # public surface: regenerate(), render_index(), Entry
    entry.py               # Entry dataclass (rel, store, date, status, role, topic, title)
    frontmatter.py         # YAML frontmatter parsing (line-anchored, no regex truncation bug)
    discovery.py           # discover_stores(repo_root) — auto-discover docs/* directories
    exclusions.py          # shared rules: drafts/, archive/, .backup suffixes, self-skip
    render.py              # render_index(entries_by_store, ...) — per-store tables + distribution
    regenerate.py          # main() — scan + render + atomic write
    cli.py                 # entry point for `oneiric plan-index regenerate --repo-root PATH`
```

Public API (importable by mahavishnu + crackerjack):

```python
from oneiric.plan_index import (
    Entry,                         # frozen dataclass
    discover_stores,               # (repo_root: Path) -> list[str]
    discover_files,                # (repo_root, store) -> list[(Path, Path)]
    regenerate,                    # (repo_root, *, out_path=None, exclude=()) -> int
    render_index,                  # (entries_by_store, *, generated_at=...) -> str
)
```

Each public function is pure / has no I/O side effects beyond the explicit `out_path` write in `regenerate()`. Tests use the pure functions directly.

### `mahavishnu/plan_index/` (master-specific)

```
mahavishnu/plan_index/
    __init__.py            # re-exports oneiric.plan_index public API
    master.py              # FleetRegenerator: walks repos.yaml, calls oneiric.plan_index for each emit_in_master entry, merges cross-repo section
    cli.py                 # `mahavishnu plan-index regenerate` CLI entry (Typer)
    format.py              # render_cross_repo_section(entries_with_origin) -> str
```

`FleetRegenerator.regenerate(out_path)` produces mahavishnu's `docs/plans/PLAN_INDEX.md`:

1. Render mahavishnu-local sections via `oneiric.plan_index.regenerate(repo_root=Path("."), out_path=tempfile1)`.
2. For each `repos.yaml` entry with `emit_in_master: true`: call `oneiric.plan_index.regenerate(repo_root=Path(entry.path), out_path=tempfile2)`; parse the rendered output; extract the per-store tables; tag each entry with `origin: <repo_name>`.
3. Concatenate: local PLAN_INDEX.md body (sans the trailing distribution section) + `## Cross-repo plans` section + distribution.

`mahavishnu/settings/repos.yaml` gets a new optional field on each entry:

```yaml
repos:
  - path: "/Users/les/Projects/oneiric"
    tags: ["substrate", "foundation"]
    description: "Foundation layer for the Bodai ecosystem"
    emit_in_master: true        # NEW: include in master fleet aggregation
  - path: "/Users/les/Projects/mahavishnu"
    tags: ["control-plane", "orchestrator"]
    description: "Control plane for the Bodai ecosystem"
    emit_in_master: true        # NEW
  # ... other core components ...
```

The default for `emit_in_master` is **false** (opt-in) so adding a sibling doesn't silently leak into the master until an operator confirms.

### `crackerjack/crackerjack/tools/plan_index_sync.py` (per-repo hook, rewritten)

Becomes a 30-line wrapper:

```python
from oneiric.plan_index import regenerate
from pathlib import Path

def main(argv: list[str] | None = None) -> int:
    parser = build_parser()
    args = parser.parse_args(argv)
    return regenerate(
        repo_root=args.repo_root.resolve(),
        out_path=args.out.resolve() if args.out else None,
    )
```

Same CLI surface (`--repo-root`, `--out`, `--dry-run`) so existing `crackerjack run --plan-index-sync` invocations continue to work. The duplicate `docs/plans/` in `DEFAULT_STORES` is gone (the shared library uses `discover_stores`).

### Sibling repos (after refactor)

For each of `oneiric`, `akosha`, `session-buddy`, `crackerjack`, `mcp-common`, `mahavishnu`:

- **DELETE**: `scripts/regenerate_plan_index.py` (the forked regenerator)
- **DELETE** (mahavishnu only): `scripts/audit_plan_index.py`, `scripts/bootstrap_plan_index.py`, `scripts/backup_plan_index.py`, `scripts/restore_plan_index_backup.py`, `scripts/backfill_plan_spec_titles.py`, `scripts/_apply_plan_audit_2026_09_12.py`
- **KEEP**: `docs/plans/PLAN_INDEX.md` (regenerated by crackerjack's hook + shared library)
- **KEEP**: `tests/unit/test_*plan_index*` and `tests/integration/plan_index/*` — moved to oneiric as the canonical test suite, deleted at source

## Data Flow

### Per-repo regeneration (crackerjack's fast-hook → local PLAN_INDEX.md)

```
crackerjack run
    └── plan_index_sync phase (existing fast-hook)
        └── oneiric.plan_index.regenerate(repo_root=<local>, out_path=docs/plans/PLAN_INDEX.md)
            ├── discover_stores(repo_root)
            ├── for each store: discover_files + parse_frontmatter → Entry
            ├── render_index(entries_by_store, generated_at=today)
            └── atomic write to out_path
```

Triggered automatically as part of `crackerjack run` when the `plan_index_sync` phase runs (opt-in via `crackerjack run --plan-index-sync` or auto on `--publish` when `settings.documentation.auto_plan_index_sync_on_publish: true`).

### Master regeneration (mahavishnu CLI → master PLAN_INDEX.md)

```
mahavishnu plan-index regenerate
    └── mahavishnu.plan_index.cli → FleetRegenerator.regenerate()
        ├── for each repo in repos.yaml with emit_in_master=true:
        │   └── oneiric.plan_index.regenerate(repo_root=<repo.path>, out_path=tempfile)
        │       └── parse rendered output into entries with origin=<repo.name>
        ├── oneiric.plan_index.regenerate(repo_root=<mahavishnu>, out_path=tempfile)
        │   └── parse rendered output as mahavishnu-local section
        └── concatenate: local body + "## Cross-repo plans" section + distribution
            └── atomic write to docs/plans/PLAN_INDEX.md
```

The master can also be regenerated as part of `crackerjack run --plan-index-sync` in mahavishnu: the crackerjack fast-hook checks if the current repo is mahavishnu and runs `FleetRegenerator` instead of `oneiric.plan_index.regenerate` directly. (Implementation detail of the crackerjack hook; out of scope for the spec beyond noting it.)

## Trigger surface

| Action | Command | Frequency |
|--------|---------|-----------|
| Per-repo local regeneration | `crackerjack run --plan-index-sync` (or auto on publish) | Per-commit / per-publish |
| Master fleet regeneration | `mahavishnu plan-index regenerate` | On-demand |
| Manual one-off regeneration | `python -c "from oneiric.plan_index import regenerate; regenerate()"` | Per any consumer

There is **no** scheduled regeneration. Master freshness is whatever the operator's last `mahavishnu plan-index regenerate` produced. (Documented as a deliberate choice: pull-on-demand is simpler than cron, and the master is a navigation aid, not a source of truth.)

## Master PLAN_INDEX.md format (variant A)

The rendered master looks like:

```markdown
---
status: active
role: canonical
date: 2026-10-19
last_reviewed: 2026-10-19
superseded_by: null
blocks_on:
  - docs/schemas/document-frontmatter-v1.md
topic: convergence-control-plane
---

# Plan Index

**Date:** 2026-10-19
**Last regenerated:** 2026-10-19
**Purpose:** Navigation map for finding and reviewing active Mahavishnu/Bodai plans.
Generated by `mahavishnu.plan_index.FleetRegenerator`. Do not edit by hand.

[... existing per-store tables: Architecture Decision Records, Plans & Specifications, etc. — unchanged ...]

[... Lifecycle × Role Distribution ...]

## Cross-repo plans

_One section per sibling repo with `emit_in_master: true`. Each row carries the origin repo in the link text._

### `oneiric` (substrate/foundation)

| Path | Date | Status | Role | Topic | Title |
|---|---|---|---|---|---|
| [`oneiric/docs/plans/2026-10-11-move-llm-and-prompting-from-mcp-common-to-oneiric.md`](oneiric/docs/plans/2026-10-11-move-llm-and-prompting-from-mcp-common-to-oneiric.md) | 2026-10-11 | `active` | `implementation` | `adapter-registry` | Move LLM and Prompting Subsystems from mcp-common to oneiric |
| ... | ... | ... | ... | ... | ... |

### `akosha` (seer/intelligence)

| Path | Date | Status | Role | Topic | Title |
|---|---|---|---|---|---|
| [`akosha/docs/plans/...`](akosha/docs/plans/...) | ... | ... | ... | ... | ... |
```

Each cross-repo sub-section uses the same per-store table format as local sections. The link target uses an absolute-style prefix (`oneiric/docs/...`) because the master is rendered at `mahavishnu/docs/plans/PLAN_INDEX.md` — two `../` deep. The rendering library handles the relative-path math; cross-repo paths become `../../oneiric/docs/plans/foo.md`. Algorithm: target = `../../` + `repos[i].path-rel` + `/` + `entry.rel`, computed per render and emitted as the markdown link href.

## Error handling

| Condition | Behavior | Exit code |
|-----------|----------|-----------|
| `repos.yaml` missing or unparseable | Abort with clear error: "Cannot read repos.yaml at <path>" | 2 |
| Sibling repo path doesn't exist | Log warning: "skipping <name>: path <p> does not exist"; continue | 0 |
| Sibling PLAN_INDEX.md missing | Log warning: "skipping <name>: no PLAN_INDEX.md at <path>"; continue | 0 |
| Sibling PLAN_INDEX.md unparseable (mid-migration) | Log warning: "skipping <name>: PLAN_INDEX.md at <path> did not parse"; continue | 0 |
| Sibling path unreadable | Log warning: "skipping <name>: permission denied on <path>"; continue | 0 |
| Local repo path doesn't exist | Abort (operator error, not a federation concern) | 2 |

Master regeneration never aborts on a single sibling's failure. The operator gets a complete master with the missing ones flagged in stderr; the fleet-level view degrades gracefully.

Per-repo regeneration has the same abort-vs-warn semantics for the local repo (the operator pointed the hook at it; failing to read it is an error). For the fast-hook case where the local repo IS the current repo, this is invariant.

## Migration plan (sequence)

Per `feedback-bodai-push-is-user-controlled.md`, every push is user-controlled. Each phase lands in its own `main` push on its own repo. The user owns the merge order.

1. **Phase 1 — Lift to oneiric**: Oneiric lands `oneiric/plan_index/*` plus tests. Move the canonical tests from each sibling (where they exist) into `oneiric/tests/plan_index/`. Existing `tests/unit/test_task_router.py::TestYAMLRoutingSync` style sync guard moves to `oneiric/tests/plan_index/test_yaml_routing_sync.py`.
2. **Phase 2 — Rewire crackerjack**: crackerjack's `plan_index_sync.py` becomes a 30-line wrapper around `oneiric.plan_index.regenerate`. The duplicate `docs/plans/` is gone. Existing test phases move under oneiric's suite.
3. **Phase 3 — Delete the 7 forks**: Each sibling deletes its `scripts/regenerate_plan_index.py`. mahavishnu deletes the 5 extras (`audit_plan_index.py`, `bootstrap_plan_index.py`, `backup_plan_index.py`, `restore_plan_index_backup.py`, `backfill_plan_spec_titles.py`, `_apply_plan_audit_2026_09_12.py`). No replacement shims per `feedback-no-backwards-compat-pre-1.0.md`. Crackerjack's hook still runs on every sibling, so local regeneration continues without per-repo scripts.
4. **Phase 4 — Master generator**: `mahavishnu/plan_index/*` lands. `mahavishnu plan-index regenerate` CLI exposed. `repos.yaml` gets `emit_in_master: true` on each of the 6 Bodai core entries (oneiric, akosha, session-buddy, crackerjack, mcp-common, mahavishnu). Master regenerator tested in integration against all 6.
5. **Phase 5 — One-off cleanup**: Rename `oneiric/.claude/decisions/2026-10-11-dhara-substrate-refs-cleanup.md` → `2026-10-11-substrate-refs-cleanup.md` (per the user's 2026-10-19 directive: don't surface Dhara in bodai context). Regenerate oneiric's local PLAN_INDEX.md to reflect the rename.

Per `feedback-mcp-common-version-bump-is-user.md`, no `pyproject.toml` version bumps in this work.

## Testing strategy

### Unit (in `oneiric/tests/plan_index/`)

- `test_frontmatter.py` — line-anchored parser (covers the truncation bug from the legacy regex); rejects malformed YAML.
- `test_discovery.py` — `discover_stores` honors system-dir pruning (`node_modules`, `.venv`, `.git`, `dist`, etc.); auto-promotes directories with ≥2 frontmatter'd files; honors `MIN_STORE_DOCS` threshold.
- `test_exclusions.py` — drafts/ subdirectory skipped; archive/ paths skipped; `.backup` / `.backup.json` suffixes skipped; self-skip on PLAN_INDEX.md.
- `test_render.py` — per-store table format; stable sorting by date DESC, path ASC; distribution matrix; entry-link relative-path math (covers cross-repo prefix logic).
- `test_regenerate.py` — atomic write (tempfile + rename); `--check` mode; `--out` override; default out_path.

### Integration (in `mahavishnu/tests/integration/plan_index/`)

- `test_master_regenerate.py` — fleet regen over a temp tree with 2 fake siblings; verifies Cross-repo section is appended; verifies per-repo entries are tagged with origin.
- `test_repos_yaml_discovery.py` — repos.yaml parsing; opt-in default (missing `emit_in_master` → excluded); malformed YAML → clear error.
- `test_master_error_handling.py` — missing sibling path → warn + continue; unparseable sibling PLAN_INDEX.md → warn + continue; final output excludes the failed sibling.
- `test_e2e_smoke.py` — existing fast-hook-style e2e; extended to verify the master regenerator runs cleanly end-to-end against real sibling checkouts.

### Regression

- The crackerjack test phase (`tests/unit/test_plan_index_sync.py` and `tests/core/test_plan_index_sync_phase.py`) moves to `oneiric/tests/plan_index/test_crackerjack_hook.py` with the duplicate-`docs/plans/` assertion removed (the underlying bug is fixed at the library level; the test now ensures the singleton invariant).

## Risks

1. **Sibling staleness**: The master pulls at regen time. If a sibling's local index is stale, the master is stale. Mitigated by the per-repo fast-hook running on every `crackerjack run` — but only if the operator actually runs crackerjack on that sibling. Documented as "freshness depends on operator behavior"; the master is a navigation aid, not a source of truth.
2. **Path configuration drift**: `repos.yaml` `path:` fields are absolute paths. If a sibling repo moves, the entry silently points at nothing. The graceful-skip-on-missing behavior turns this into a stderr warning, not an abort. Documented in the error-handling table.
3. **One-off cleanup race**: If Phase 5 (rename of the dhara decision file) lands after Phase 4 (master regenerator), the master's first regen includes the dhara-named entry. Mitigate by sequencing Phase 5 first or by accepting one stale master regen. Documented.
4. **Backwards-incompat surface area**: All 7 forks deleted simultaneously per `feedback-no-backwards-compat-pre-1.0.md`. If a sibling isn't on the same release train, it can't regenerate locally until crackerjack's hook rewires (Phase 2). Sequencing: Phase 1 + Phase 2 must land atomically per repo before Phase 3 deletion in that repo.

## Non-goals

- Real-time master freshness (webhooks, cron). Pull-on-demand only.
- Bidirectional cross-repo plan linking (e.g., "this plan depends on that plan in another repo"). Future work.
- Inline plan content aggregation. We surface metadata (date, status, topic, title) not full plan bodies.
- Permissions / ACLs on who can run the master regenerator. Assumed: any operator with filesystem write access to `mahavishnu/docs/plans/PLAN_INDEX.md`.

## Review focus

Five input classes the spec implies but no test in any task explicitly exercises:

1. **A `repos.yaml` entry with `emit_in_master: true` but a relative path** (e.g., `path: ./oneiric` instead of absolute) — expected behavior: reject at parse time with a clear error. *Pinned to: `oneiric/tests/plan_index/test_repos_yaml_validation.py::test_relative_path_rejected`.*
2. **Two siblings with identical `repos.yaml` paths** — expected behavior: dedupe (warn, take the first); don't emit duplicate "in this section". *Pinned to: `mahavishnu/tests/integration/plan_index/test_master_dedup.py::test_duplicate_repo_path_dedupes`.*
3. **A sibling whose `docs/plans/PLAN_INDEX.md` has the same plan listed twice** (the very bug we fixed in oneiric) — expected behavior: master renders each row once (last-wins or first-wins, deterministic). *Pinned to: `mahavishnu/tests/integration/plan_index/test_dedup.py`.*
4. **The master PLAN_INDEX.md is regenerated while a previous regeneration is still in flight** (concurrent runs against the same output file) — expected behavior: atomic rename ensures one wins, the other becomes a backup at `<out_path>.bak` (or the temp file gets cleaned up by the next run). *Pinned to: `oneiric/tests/plan_index/test_concurrent_writes.py::test_atomic_rename_winner_takes_all`.*
5. **A sibling that has a `docs/plans/` directory but no `PLAN_INDEX.md` and a stale auto-discovery result** — expected behavior: regen of that sibling's local index via crackerjack's hook fills in the missing file; master regen skips it with a warning. *Pinned to: `mahavishnu/tests/integration/plan_index/test_missing_local_index.py`.*
