# Master Plan Index + Centralized Regenerator — Design Spec (Round 2)

## Goal

A single `PLAN_INDEX.md` in `mahavishnu/docs/plans/` (the "master") that aggregates the plan/decision/spec corpus across the 6 Bodai core components. The 7 forked `regenerate_plan_index.py` scripts collapse into one shared library in `oneiric.plan_index`. Pull-on-regeneration, no federation layer, no push surface in siblings.

**Out of scope (handled by separate workstreams — see "Workstreams not in this spec" below):**
- Removing the Dhara-canonical CRUD layer (`mahavishnu/plan_index/{store,rebuild,render,cron,cron_core,writer,health,record,types,testing,errors,paths,url}.py`) and the 5 `mcp__mahavishnu__plan_*` tools it powers.
- Renaming Dhara-named decision files outside `oneiric/.claude/decisions/2026-10-11-dhara-substrate-refs-cleanup.md`.
- Removing Dhara references from `oneiric/adapters/tracked_settings.py`, `docs/runbooks/MIGRATE_PLAN_INDEX_DHARA.md`, etc.

## Background

Today (2026-10-19):
- 7 Bodai core repos each ship their own copy of `regenerate_plan_index.py` (and mahavishnu has 5 additional plan-index scripts: `audit_plan_index.py`, `bootstrap_plan_index.py`, `backup_plan_index.py`, `restore_plan_index_backup.py`, `backfill_plan_spec_titles.py`, `_apply_plan_audit_2026_09_12.py`).
- `mahavishnu/docs/plans/PLAN_INDEX.md` frontmatter claims `topic: convergence-control-plane` ("Navigation map for finding and reviewing active Mahavishnu/Bodai plans") but the regenerator only walks mahavishnu's own tree. The claim is aspirational; the artifact doesn't deliver.
- **`mahavishnu/plan_index/` exists with completely different semantics** — it's a 12-file Dhara-canonical CRUD layer (`PlanIndexStore`, `PlanIndexRebuilder`, etc.) powering 5 live MCP tools (`mcp__mahavishnu__plan_{list,show,vitals,search,rebuild_status}`) and the `mahavishnu plan {list,show,vitals,search,purge}` CLI. **This spec does not modify that layer.** (Round 1's collision finding — see Decisions #6 below.)
- Open bug surfaced during Round 1 design: `crackerjack/crackerjack/tools/plan_index_sync.py:DEFAULT_STORES` listed `docs/plans/` twice; oneiric's PLAN_INDEX.md (regenerated by crackerjack's hook) had a verbatim duplicate `### Docs: plans` block. **Already fixed as a side task on 2026-10-19**; the new library pins the singleton invariant so this can't regress.

## Architecture

The regenerator logic moves into `oneiric/plan_index/` as a shared library. Per-repo regeneration goes through crackerjack's existing fast-hook, which now imports the library instead of carrying its own implementation. The master regenerator lives at `mahavishnu/fleet_index/` (a NEW package; **not** at `mahavishnu/plan_index/`) and consumes the same library for each `emit_in_master: true` entry in `settings/ecosystem.yaml`, appending a `## Cross-repo plans` section to mahavishnu's local `PLAN_INDEX.md`. There are no inbound surfaces in sibling repos: they keep generating their own `PLAN_INDEX.md` locally; the master pulls them at regeneration time.

Crackerjack's per-repo hook carries a **transition feature flag** (`settings.documentation.use_shared_regenerator: bool`) so Phase 1 (oneiric land) and Phase 2 (crackerjack rewires) can ship independently of Phase 3 (per-sibling deletion). Until a sibling sets the flag and deletes its fork, that sibling still works on the legacy path.

## Decisions (locked in brainstorming)

1. **Master PLAN_INDEX.md lives in `mahavishnu/docs/plans/PLAN_INDEX.md`** — single file with both mahavishnu-local content and a `## Cross-repo plans` section (variant A).
2. **Shared regenerator library lives in `oneiric/plan_index/`**.
3. **Sync model: pull on regeneration** — master walks siblings at regen time. No push surface in sibling repos. No cron, no webhook.
4. **Discovery reads `mahavishnu/settings/ecosystem.yaml`** (the canonical manifest, per `settings/repos.yaml:1`'s explicit DEPRECATED notice). Add optional `emit_in_master: true` to opt in. Default false.
5. **Fork disposition: delete the 7 forks** per `feedback-no-backwards-compat-pre-1.0.md`. Crackerjack's `crackerjack/tools/plan_index_sync.py` rewires to `oneiric.plan_index` and remains the per-repo fast-hook.
6. **New master package: `mahavishnu/fleet_index/`** (NOT `mahavishnu/plan_index/`). The existing `mahavishnu/plan_index/` package (Dhara-canonical CRUD) is preserved untouched — different feature, separate workstream. The new CLI is `mahavishnu fleet regenerate` (NOT `mahavishnu plan-index regenerate`) — avoids namespace collision with `mahavishnu plan {list,show,vitals,search,purge}`.
7. **CLI placement: `oneiric/cli/plan_index.py`** declaring `plan_index_app = typer.Typer(...)`, registered against `oneiric/core/cli.py:app` via `app.add_typer(plan_index_app, name="plan-index")`. NOT `oneiric/plan_index/cli.py` (bypasses the shared `OneiricCLIBase`).
8. **Frontmatter parsing reuses `oneiric/schemas/document-frontmatter-v1.md`** — the existing 8-key schema (status/role/date/last_reviewed/superseded_by/blocks_on/topic) + lite variant for `.claude/decisions/`. The library reads + validates against this schema; does NOT redefine vocabulary.
9. **Public library API exposes `scan_entries(repo_root) -> dict[str, list[Entry]]`** as a first-class function. `regenerate()` becomes a thin composition of `scan_entries + render_index + atomic_write`. Master regenerator composes `scan_entries + render_index` per sibling; no markdown round-trip in the consumer.
10. **Crackerjack transition: feature flag per repo** (`settings.documentation.use_shared_regenerator: false` by default). Phase 2 ships the new hook; each sibling flips the flag in its own release train; only then deletes the fork (Phase 3). No forced atomic per-repo coordination across the 6 cores.

## Component responsibilities

### `oneiric/plan_index/` (new shared library)

```
oneiric/plan_index/
    __init__.py            # public surface: re-exports Entry, discover_stores, discover_files, scan_entries, render_index, regenerate
    entry.py               # Entry dataclass (rel, store, date, status, role, topic, title)
    frontmatter.py         # wraps oneiric.schemas.document_frontmatter.parse() + validate(); line-anchored on `---` markers
    discovery.py           # discover_stores(repo_root) — auto-discover docs/* directories; DEDUP invariant: Sequence[str] preserves first-seen order, never duplicates
    exclusions.py          # shared rules: drafts/, archive/, .backup suffixes, self-skip on PLAN_INDEX.md
    render.py              # render_index(entries_by_store, *, generated_at=...) -> str
    regenerate.py          # regenerate(repo_root, *, out_path=None, exclude=(), check=False) -> int

oneiric/cli/plan_index.py  # NEW: typer.Typer("plan-index") entry; registers in oneiric/core/cli.py
oneiric/cli/__init__.py   # existing — see imports
oneiric/core/cli.py       # existing — see imports
```

Public API (importable by mahavishnu + crackerjack):

```python
from oneiric.plan_index import (
    Entry,                         # frozen dataclass: rel, store, date, status, role, topic, title
    discover_stores,               # (repo_root: Path) -> Sequence[str]; dedup invariant
    discover_files,                # (repo_root: Path, store: str) -> list[tuple[Path, Path]]; first Path is absolute, second is repo-relative
    scan_entries,                  # (repo_root: Path) -> dict[str, list[Entry]]; SKIPS the markdown round-trip
    render_index,                  # (entries_by_store, *, generated_at=...) -> str
    regenerate,                    # (repo_root: Path, *, out_path: Path | None = None, exclude=(), check=False) -> int
)
```

`regenerate` returns the count of entries written. Default `out_path` is `<repo_root>/docs/plans/PLAN_INDEX.md` (matches the existing crackerjack convention). When `check=True`, it diffs the rendered output against the existing file and exits 1 on drift (matches crackerjack's existing `--check` semantics).

### `oneiric/schemas/document-frontmatter-v1.md` (existing — reused, not modified)

Already canonicalizes the 8-key frontmatter vocabulary. The library's `frontmatter.py` parses YAML between the existing `---\n` markers and validates against this schema. No new vocabulary. No new parser.

### `mahavishnu/fleet_index/` (NEW — master regenerator, NOT a new `plan_index/`)

```
mahavishnu/fleet_index/
    __init__.py            # public surface: re-exports oneiric.plan_index public API
    master.py              # FleetRegenerator: walks ecosystem.yaml, calls oneiric.plan_index.scan_entries for each emit_in_master entry, merges cross-repo section
    format.py              # render_cross_repo_section(entries_by_origin) -> str; per-repo subsections tagged with origin: <slug>
    cli.py                 # `mahavishnu fleet regenerate` Typer entry; registers in mahavishnu/_main_cli.py
```

`FleetRegenerator.regenerate(out_path)` produces `mahavishnu/docs/plans/PLAN_INDEX.md`:

1. Render mahavishnu-local sections via `oneiric.plan_index.regenerate(repo_root=Path("."), out_path=tempfile1)`.
2. For each `ecosystem.yaml` entry with `emit_in_master: true`: call `oneiric.plan_index.scan_entries(repo_root=Path(entry.path))`; tag each entry with `origin: <entry.slug>`.
3. Concatenate: local body (sans distribution footer) + `## Cross-repo plans` section + a single shared distribution footer (via `oneiric.plan_index.render_index.distribution_footer(entries)` — a third public-API helper, NOT a parsed-and-re-emitted string from the local regen's output).
4. Atomic rename to final path. Pre-existing tempfiles cleaned by next regen.
5. Return exit code: 0 if all siblings regenerated cleanly OR `--check` mode reports no drift; 1 if any sibling failed or drift detected (aggregate failure signal — see Error Handling).

`mahavishnu/settings/ecosystem.yaml` gets a new optional field on each entry:

```yaml
- name: oneiric
  package: oneiric
  path: /Users/les/Projects/oneiric
  ...
  emit_in_master: true        # NEW: include in master fleet aggregation
```

Default for `emit_in_master` is **false** (opt-in). Adding a sibling doesn't silently leak into the master until an operator confirms.

### `mahavishnu/plan_index/` (EXISTING — preserved untouched)

This package is the Dhara-canonical CRUD layer. It powers `mcp__mahavishnu__plan_*` and `mahavishnu plan {list,show,...}`. **This spec does not modify it.** Its decommission is a separate workstream (see "Workstreams not in this spec").

## Data Flow

### Per-repo regeneration (crackerjack's fast-hook → local PLAN_INDEX.md)

```
crackerjack run
    └── plan_index_sync phase (existing fast-hook)
        └── read settings.documentation.use_shared_regenerator
            ├── True:  oneiric.plan_index.regenerate(repo_root=<local>, out_path=docs/plans/PLAN_INDEX.md)
            │           ├── scan_entries(repo_root) → dict[str, list[Entry]]  [NEW public API]
            │           ├── render_index(entries_by_store, generated_at=today)
            │           └── atomic write to out_path
            └── False: legacy local implementation (deleted in Phase 3 of each sibling)
```

Triggered automatically as part of `crackerjack run` when the `plan_index_sync` phase runs (opt-in via `crackerjack run --plan-index-sync` or auto on `--publish` when `settings.documentation.auto_plan_index_sync_on_publish: true`).

### Master regeneration (mahavishnu CLI → master PLAN_INDEX.md)

```
mahavishnu fleet regenerate [--check] [--dry-run]
    └── mahavishnu.fleet_index.cli → FleetRegenerator.regenerate()
        ├── oneiric.plan_index.scan_entries(repo_root=mahavishnu) → local entries
        │   └── render local body
        ├── for each entry in ecosystem.yaml with emit_in_master=true:
        │   ├── oneiric.plan_index.scan_entries(repo_root=<entry.path>) → sibling entries
        │   └── tag entries with origin: <entry.slug>
        ├── assemble: local body + "## Cross-repo plans" section + distribution footer
        └── atomic write to docs/plans/PLAN_INDEX.md; exit code = aggregate (0/1)
```

`mahavishnu/_main_cli.py:1488` registers the existing `plan_app` group; this spec adds `fleet_app = typer.Typer(...)` and `app.add_typer(fleet_app, name="fleet")`. Operators who already use `mahavishnu plan {list,show,vitals,search,purge}` continue to use those subcommands; the new `mahavishnu fleet regenerate` is the fleet-level sibling.

## Trigger surface

| Action | Command | Frequency |
|--------|---------|-----------|
| Per-repo local regeneration (new path) | `crackerjack run --plan-index-sync` (auto-routed via feature flag) | Per-commit / per-publish |
| Per-repo local regeneration (legacy path) | `crackerjack run --plan-index-sync` (when flag is false) | Until Phase 3 in that sibling |
| Master fleet regeneration | `mahavishnu fleet regenerate` | On-demand |
| Master drift check (no write) | `mahavishnu fleet regenerate --check` | Per-CI / pre-merge |
| Manual one-off via Python | `python -c "from oneiric.plan_index import regenerate; regenerate()"` | Per any consumer |

There is **no** scheduled regeneration. Master freshness is whatever the operator's last `mahavishnu fleet regenerate` produced.

Each cross-repo sub-section uses the same per-store table format as local sections. Link target uses `ecosystem.yaml` entry's `slug` field (stable, distinct from basename) prefixed by `../../`. The `slug` field is required on every `emit_in_master: true` entry — sync-guard test fails if missing.

## Error handling

| Condition | Behavior | Exit code |
|-----------|----------|-----------|
| `ecosystem.yaml` missing or unparseable | Abort with clear error: "Cannot read ecosystem.yaml at <path>" | 2 |
| `emit_in_master: true` entry missing `slug` field | Abort with clear error: "<name> has emit_in_master but no slug"; do not emit partial master | 2 |
| Sibling repo path doesn't exist | Log warning: "skipping <name>: path <p> does not exist"; continue | 1 (any sibling failure → 1) |
| Sibling PLAN_INDEX.md missing | Log warning: "skipping <name>: no PLAN_INDEX.md at <path>"; continue | 1 |
| Sibling scan fails (frontmatter parse error, I/O) | Log warning: "skipping <name>: <error>"; continue | 1 |
| Sibling path unreadable | Log warning: "skipping <name>: permission denied on <path>"; continue | 1 |
| Local repo path doesn't exist (master regen) | Abort (operator error) | 2 |
| Master regen `--check` mode detects drift | Log "drift detected; <details>"; abort | 1 |
| **Final aggregate** | Log "regenerated: N / M; failed: [list]"; exit 0 if all clean, 1 if any failed | 0/1 |

Per-repo regeneration: abort on local failure (operator pointed the hook at it). For crackerjack's fast-hook case where the local repo IS the current repo, this is invariant.

## Risks

1. **Sibling staleness**: The master pulls at regen time. If a sibling's local index is stale, the master is stale. Mitigated by the per-repo fast-hook running on every `crackerjack run` (and by `--check` mode catching drift in CI).
2. **Path configuration drift**: `ecosystem.yaml` `path:` fields are absolute paths. If a sibling repo moves, the entry silently points at nothing. The graceful-skip-on-missing behavior turns this into a stderr warning + exit code 1, surfacing the drift in CI. Documented in the error-handling table.
3. **Cross-repo link drift**: Cross-repo link targets depend on `slug` fields in `ecosystem.yaml`. If an operator renames a slug, links break. The sync-guard test pins the invariant.
5. **Phase ordering with the separate Dhara-decommission workstream**: If that workstream deletes `mahavishnu/plan_index/store.py` (and breaks the 5 `mcp__mahavishnu__plan_*` tools) before this spec ships Phase 1, the test fixtures that depend on the live `mcp__mahavishnu__plan_*` surface break. Mitigation: this spec's e2e tests use the new filesystem-scanner master, not the MCP-backed CRUD store. Coordinate with the Dhara-decommission workstream via shared Phase sequencing.

- Permissions / ACLs on who can run the master regenerator. Assumed: any operator with filesystem write access to `mahavishnu/docs/plans/PLAN_INDEX.md`.

- Inline PLAN_INDEX.md header sections (status legend, authority matrix, etc.) — those are hand-curated today and stay hand-curated post-Phase 4. The regenerator renders only the per-store tables and the distribution footer.

Five input classes the spec implies but no test in any task explicitly exercises:

1. **An `ecosystem.yaml` entry with `emit_in_master: true` but a relative path** (e.g., `path: ./oneiric` instead of absolute) — expected behavior: reject at parse time with a clear error. *Pinned to: `mahavishnu/tests/integration/fleet_index/test_ecosystem_yaml_validation.py::test_relative_path_rejected`.*

4. **The master PLAN_INDEX.md is regenerated while a previous regeneration is still in flight** (concurrent runs against the same output file) — expected behavior: `os.replace` overwrites atomically on POSIX; last writer wins; no `.bak` file is produced (the spec text was overcautious in Round 1). *Pinned to: `oneiric/tests/plan_index/test_atomic_writes.py::test_concurrent_writes_last_writer_wins`.*
