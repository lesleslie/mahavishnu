## Interpretation

The bug pattern is: a Python file uses `from __future__ import annotations`
(the crackerjack convention) and ALSO imports a name under `if TYPE_CHECKING:`,
but that name is referenced at runtime (e.g., instantiated, used as a base
class, used in `isinstance`) outside any annotation context.

Under `from __future__ import annotations`, annotations are stringified at
runtime — they never trigger a name lookup. But non-annotation references do.
When the runtime path executes, those names are undefined and Python raises
`NameError: name 'X' is not defined` (or, for Pydantic models,
`PydanticUserError: class-not-fully-defined`).

## Fix (per violation)

```python
# Before (broken at runtime):
from __future__ import annotations
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from foo import Bar

def make():
    return Bar()  # NameError!

# After:
from __future__ import annotations
from foo import Bar  # always available

def make():
    return Bar()  # works
```

Or, if the import is genuinely expensive and only used for typing, use a
runtime fallback:

```python
from __future__ import annotations
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from foo import Bar
else:
    Bar = None  # type: ignore[assignment]
```
